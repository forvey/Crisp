# 共享增强双端诊断

共享增强的「高级 → 诊断（音频、画面）…」提供音频、画面卡顿和画面清晰度诊断。
在 Crisp 开启原有远程音频服务即可；主控扬声器/麦克风不必开启，诊断不会主动启动采集设备。

- 同一 TCP 49555 监听器按第一帧区分音频与诊断；当前音频协议为 v2，诊断协议仍为 v1。共享增强与 Crisp 必须配套升级，旧版音频连接会被拒绝。
- 诊断前言：`uint32_be length + SSE-CRISP-DIAGNOSTICS/1`；后续同样长度前缀的 JSON，最大 256 KiB，`version=1`、UUID 会话编号，开始时选 screen/audio/both，时长 1–60 秒。较大上限仅供 HiDPI 参考 PNG，不改音频帧上限，不增加日常采样。
- 客户端消息：start、ping、pattern、patternStop、motionStart、motionPrepare、motionRun、motionStop、qualityStart、qualityStop、stop。服务端消息：started、pong、sample、motionResult、qualityReady。`started.note` 的 `motion-v2`/`quality-v2` 分别声明先识别再开始动画、按实际显示倍率绘制清晰度图；新主控不向不支持的旧端发送对应命令。仍保留 `motion-v1` 给旧客户端；不再声明 `quality-v1`，防止旧主控把 2× 图当成旧固定尺寸。每秒资源快照；音频路径只在音频诊断开启时累计有界计数和直方图。不同主机时钟保留偏移误差，不声称精确单向延迟。
- 主控必须明确启动短测才出现图案窗口；图案显示在 mini 鼠标所在显示器，走已有屏幕共享，不开第二路远程视频，不执行任意输入或抓取 mini 业务截图。
- 主控断开、服务关闭、睡眠时回收；mini 独立 60 秒上限，连续图案另有 15 秒期限，旧客户端逐次图案 5 秒无请求自动关闭。服务菜单显示正在诊断。
- 默认没有诊断采样器/计时器/连接/图案窗口。开启后最多一个诊断会话、每秒 30 条请求、三个待完成发送；超过限制关闭诊断，不影响音频连接。资源读取及报告序列化在单独队列完成，不占用音频发送队列。

覆盖相关进程 CPU/内存/磁盘、系统 CPU、温度压力/交换空间、接口类型和控制请求往返；音频覆盖发送间隔/积压、采集缺帧/回调年龄、麦克风排队/丢弃及 HAL 写入。不能据此断言屏幕编码/解码耗时、实际音频 TCP 重传或通话应用已消费音频，缺失项保留在报告中。

资源口径：进程 CPU 的 100% 表示一颗逻辑核心；磁盘字节为两次采样间的差值。
兼容现有 0.5.1 报告的 `residentBytes` 字段实际取自 `ri_phys_footprint`，表示物理内存足迹，
不能与外部工具的 RSS 直接比较。系统不允许读取的进程计数必须保留缺口，不能按零值判断。

端口沿用现有可信局域网边界，无新增认证/TLS，不应直接暴露公网。主控报告只含数值，不含录音或截图。

离线验证使用 `CRISP_CONTROLLER_SOURCE=<共享增强仓库> scripts/check-remote-audio.sh`；只有 Command Line Tools 时设置 `DEVELOPER_DIR=/Library/Developer/CommandLineTools`。用真实 TCP 服务及合成音频后端，不安装或启动硬件设备。完整应用构建是 `make compile`，不是会替换已安装应用的 `make dev`。

显式增加 `--full-lifecycle` 会实际等待一分钟，并在 mini 本地手动触发图案组件验证
（颜色编码、停止和无指令自动关闭），不创建远程视频、不采集音频。
普通调用不会显示图案；这项本地验证不能替代 MacBook 的窗口采样与真实共享链路验收。

## 连续画面诊断

主控明确点击「画面卡顿诊断」后，`motionPrepare.sequence` 携带本次标记（1–4095）。仅屏幕诊断且剩余至少 20 秒接受；同一会话只允许一项动画。mini 先显示静态编号，本机识别成功才发 `motionRun`（同一标记，剩余至少 16 秒）；之后 mini 自主按 30 fps 绘制 15 秒移动条纹和 24 位编号（12 位测试标记 + 12 位帧号），不是主控逐帧下发。准备 5 秒未收到 Run 自行关闭，静态等待不算动画卡顿。旧 `motionStart` 保留直接开始语义。

实际 `draw` 完成才记录编号/单调时间，最多 512 条，不保存任何屏幕像素。15 秒到期、显式停止或会话关闭时销毁动画计时器与窗口；停止消息校验会话及本次标记，旧停止不能干扰下一次测试。`motionResult` 一次返回绘制记录、开始/结束时间与是否完整结束，受 256 KiB 消息上限约束。正常关闭动画后不会继续绘制或采样，平时不创建这些对象。

主控准备最多 4 秒、识别后最多观察 18 秒，以最高 60 fps 临时读取单个共享窗口；未授权、未取得画面、有画面但未识别分别报告，不会直接跑完 15 秒再笼统报无结果。导出包含授权、有效捕获/未识别/错误标记次数及准备耗时。报告 ≥100 ms 重复画面、编号更新间隔、未观察到的帧和无法判断的时长。没有采样回调不补造冻结证据；编号跳跃不等于网络丢包。双端时钟误差不超过 20 ms 时才比较源端绘制与本机停顿是否重合。绘制完成不证明原生合成/编码完成，此测试不能直接定位 Apple 内部单段耗时，也不代表所有应用场景。

本次主控合成测试覆盖正常更新、400 ms 共享画面冻结/mini 停画、采样缺口及提前停止。Crisp 的 `--full-lifecycle` 新增自主绘制、旧停止隔离、部分结果和 15 秒自动结束检查，需在 mini 执行；本轮未在主控构建或运行 Crisp，也未验证真实双机采样。

### 停顿补充证据（screen-evidence-v1）

只有 `motionPrepare/motionStart.collectScreenTrace=true` 才启动补充采集，旧主控、音频和清晰度不启动。mini 从已建立的诊断连接取得真实对端 IP，不接受主控任意指定采集目标。

- `nettop` 每秒读取 screensharingd/ScreensharingAgent，仅保留本对端的 TCP 5900 连接：收发、重传、重复/乱序字节累计值，RTT、接收缓冲和发送窗口。没有权限或连接不匹配时保留缺口，不记为 0。不能把一秒统计当成某次 100 ms 停顿的逐包证据。
- 系统日志仅过滤已知 Wi-Fi 扫描与 AMD 分配失败，导出时间/耗时/类别，不保留原始日志、网络名称或业务内容。Apple Silicon 等其他图形驱动错误未覆盖；没有事件不能排除图形问题。
- 最多 128 条连接读数、256 个事件，每个子进程输出上限 256 KiB、独立 25 秒超时。动画结束即停止并随 `motionResult.screenTrace` 返回；断线、会话关闭也停止，必要时 300 ms 后结束自己的残留子进程。无日常采样，无提权、抓包或常驻服务；不改屏幕传输或音频代码。

`LagScreenTrace.swift` 与主控保持一致，互通验证脚本会核对。主控新增的回环与离线测试验证解析、协议和清理；mini 完整应用构建、真实系统事件可读性及双机运行仍须在 mini 验证，不能把主控 typecheck 当成 Crisp 已构建通过。HAL 无修改，不需因此重新安装。

## 画面清晰度诊断（quality-v2）

主控明确选择屏幕共享或 UU 窗口后发送 `qualityStart.sequence`（1–4095）。仅屏幕诊断、无其他图案任务且会话剩余至少 16 秒时接受。Crisp 在鼠标所在显示器显示 784×480 界面点的测试图：12/16/24 点中文/英文、1/2/4 点横纵细线、色块及本次编号。按显示器实际 1×/2× 倍率重新绘制为 784×480 或 1568×960 像素，同样字号的 HiDPI 图不是放大旧位图。

`qualityReady.quality` 返回 token、渲染倍率、显示器 ID、桌面与渲染分辨率、刷新率及仅程序生成的 PNG（不超过 160,000 字节，尺寸必须匹配倍率，编码后符合 256 KiB 帧上限）；不抓取或传送业务桌面截图。字体只在 mini 绘制，本机不另行生成替代参考图，也不自动切换显示配置。

被评分的是主控客户端解码、缩放后实际绘制的窗口，而不是这张参考图或后台收到的像素。主控准备最多 4 秒，识别完整图案后以 2 fps、原生窗口像素测量 10 秒；像素不落盘，只保留数字。用户分别运行两次并导出 JSON 即可比较：每次只改 HiDPI 或客户端等一个条件，不在测量途中修改。HiDPI 不同意味着参考图不同，不能只按文字差异百分比判断哪次更清楚；不同缩放也不混作传输质量排名。不测物理显示器、不直接判定编码/网络根因。

`qualityStop`、断线、服务关闭销毁图案；mini 另有独立 16 秒期限，停止后没有图像/动画任务。与现有 motion 互斥，平时不创建参考图或计时器。旧主控忽略新能力，旧 Crisp 由新主控明确提示升级。

本轮只在主控验证合成图和控制端生命周期。mini 需运行配套 `scripts/check-remote-audio.sh`、完整应用编译；`--full-lifecycle` 覆盖准备图等待/超时、匹配 Run、重复 Run 不重置、源图实际倍率、手动停止、旧会话隔离和清晰度 16 秒到期。真实屏幕共享/UU 展示对比仍待双方部署后执行。本次只需更新两端应用，已安装的 HAL 1.0.4 不因本次修改重装。
